# Selah 통합 UI와 데이터 — 공유 앱 1.0.7 / 빌드 19

Windows·Mac·iOS·웹은 같은 `index.html`, `scripts/unified-data.js`와 BlueCloud 계정의 `/api/cloud-state/selah`를 사용합니다. GitHub `main`이 UI와 데이터 계약의 원본이며 iOS의 `mobile/www`는 생성물입니다. 각 플랫폼에서 같은 계정에 로그인해야 계정 기록이 연결됩니다. 계정 없이 서로 다른 기기의 로컬 저장소가 자동으로 연결되지는 않습니다.

| 대상 | 공통 기록 | 기기에 남는 자료 |
| --- | --- | --- |
| 묵상, 퀴즈, 큐티, 출석, 경험, 성경 대화 | 안정적인 ID로 합침 | 계정별 오프라인 사본 |
| 작성 중인 노트 | 작성 창별 초안 사본; 다른 기기 초안을 불러올 수 있음 | 현재 편집 창과 직전 초안 백업 |
| 언어, 색상, 전체 글꼴 | 변경 시계를 가진 공통 설정 | 운영체제에 설치된 글꼴 자체 |
| 읽기 글꼴/크기 | desktop/mobile 각각 공통 설정 | 화면 크기에 따른 반응형 배치 |
| 읽던 장·절·위치, 묵상 타이머, 컴퓨터 읽기 요청 | 공통 진행 상태와 요청 ID | 운영체제의 창·알림·URL 실행 |
| 다운로드한 성경 본문 | 번역 언어 선택을 공유 | 큰 본문 캐시와 다운로드는 각 기기에서 보관 |

## 기록이 갈라지지 않도록 하는 규칙

- `_selahSync.version=1`에 필드/기록별 변경 시계, 삭제 표식과 복구본을 저장합니다. 서버의 `_rev`로 같은 시점의 덮어쓰기를 거부하고 `stale_state`만 최대 세 번 다시 읽어 합칩니다. `account_merged`와 인증 오류에는 캐시된 인증을 제거해 재로그인을 요구하며 기록은 남깁니다.
- 같은 ID의 서로 다른 기록은 결정적으로 하나를 현재값으로 선택하고 이전 값을 내 계정 복구 목록에 남깁니다. 삭제 표식이 이전 기록보다 새로우면 오래된 기기가 그 기록을 다시 살리지 않습니다. 새 기록으로 복구하면 별도 ID를 사용합니다.
- 초안은 설치·편집 창별 ID를 사용합니다. 다른 기기의 초안을 가져와도 직전 내 초안을 로컬 백업에 보관합니다. 동일 작성 창의 연속 자동저장은 최근 초안으로 갱신됩니다.
- `selah.accounts.v1`이 계정별 오프라인 사본을 보관합니다. 계정 전환 시 이전 계정 기록과 새 계정 기록을 자동으로 섞지 않습니다. 로그아웃은 기록 삭제가 아닙니다.
- 백업 가져오기는 기록을 추가하고 충돌본을 보관합니다. 계정 소유자·인증·서버 리비전과 실행 중인 컴퓨터 명령을 백업으로 옮기지 않습니다. 백업의 활성 초안도 별도의 가져온 초안으로 남깁니다.
- 10초 단위로 전체 기록 변경을 확인하고, 내용이 같으면 서버에 다시 쓰지 않습니다. 네트워크 복구와 화면 복귀 시 재시도합니다. 같은 브라우저의 탭 사이에서도 계정 소유자가 일치하는 기록만 합칩니다.

## UI 원본과 설치본

`SHARED_APP_BUILD.json`은 공유 화면/데이터 버전을 기록합니다. Windows 런처 ZIP 버전과 별개로, 런처와 확인한 Mac SwiftUI 소스는 같은 공개 URL을 엽니다. Mac 소스의 URL을 SSH로 확인했으며 실제 설치된 앱의 생성 소스와 실행 버전은 아직 확인되지 않았습니다.

`node mobile/scripts/copy-web.mjs`는 화면, 스타일, 공통 스크립트, 개인정보 안내와 이미지 등을 복사하고 `mobile/www/SHARED_SOURCE_MANIFEST.json`에 정규화한 SHA-256을 기록합니다. `--check`는 원본과 번들이 다르면 실패합니다. iOS/Android sync 명령과 GitHub CI가 이 검사를 실행합니다. 실제 iOS 설치본에 새 코드가 들어가려면 Mac에서 같은 원본을 동기화하고 새 빌드를 설치해야 합니다. 원래 WebView 저장소를 삭제하거나 앱을 제거하는 방식으로 업데이트하지 마세요.

스페인어·포르투갈어·타갈로그 전용 읽기 페이지의 기존 메모·북마크·형광 표시는 공유 앱 1.0.10/build24에서 자동 이관합니다. 같은 브라우저/프로필/웹 origin에 있는 `selah.reader.es.v1`, `selah.reader.pt-br.v1`, `selah.fil.reader.v1`이 대상입니다. 주 앱의 selah.v1은 기존 IDs 그대로 사용합니다. 다른 브라우저/기기/서버 origin의 로컬 기록은 그곳에서 내보낸 Selah 백업을 통합 앱의 백업 가져오기로 추가해야 합니다.

## 확인된 증거와 남은 검증

- 공통 코어 시험 13개: 세 기기 기록 수렴, 충돌본 보존, 삭제, 기존 클라이언트 타임스탬프, 화면 설정, 백업 추가, 초안, 확장 필드, 성경/화면 언어 분리, 요청 결과 매칭, 미래 스키마 보호와 시계 차이.
- Headless Edge의 분리된 Windows/Mac/iOS 화면에서 실제 페이지와 동기화 함수를 실행했습니다. 합성 계정/API로 오프라인 저장, `_rev` 충돌, 무변경 시 쓰기 방지, 삭제, 설정, 초안, 다른 계정 격리와 `account_merged` 중단이 통과했습니다. 실제 사용자의 토큰·노트는 읽거나 쓰지 않았습니다.
- 원본/모바일 파일 37개의 일치 검사와 기존 폰트·출석 검사를 실행했습니다.
- Brainwire 로컬 `origin/main`의 `server/routes/cloudAppState.js`는 인증된 계정+appId 별 전체 문서 저장과 `_rev` 비교를 구현합니다. 서버 코드는 이번 작업에서 변경하지 않았습니다. 현재 생산 서버의 인증된 GET→PUT→GET, 설치된 Mac/iOS 앱의 실제 동기화와 iOS 업데이트 후 로컬 기록 유지 검증은 아직 남아 있습니다.

Mac 적용 요청은 `docs/handoffs/20261002-selah-unified-data-mac.md`에서 관리합니다. 사용자 기록 전체의 병합 완료를 선언하려면 업데이트된 각 앱에서 같은 계정으로 연결된 실제 결과를 확인해야 합니다.

## 기존 기록 이관 — 1.0.10 / build24

- 자동 이관은 로컬 원본 백업 저장이 성공한 뒤에만 시작합니다. 원본 키는 삭제/교체하지 않습니다. 원본과 당시 주 앱 백업은 계정 화면에서 내려받을 수 있습니다. 손상된 JSON은 자동 이관하지 않으며 원본을 남깁니다.
- 원본 메모는 일반 묵상으로, 북마크/형광 표시는 readerMarks로, 해석하지 않은 필드는 legacyReaderArchives로 보관합니다. 원본에 작성 일자가 없으면 임의의 출석일을 만들지 않습니다.
- 원본/내용에 따른 안정적인 ID와 원본 지문으로 재실행 중복을 막습니다. 옛 페이지에서 내용이 달라지면 추가 버전으로 남기고 현재 시스템의 편집 내용을 덮어쓰지 않습니다. 공유 앱에서 삭제한 기록은 배경 재검사로 살리지 않습니다.
- 계정별 이관 claim이 다른 계정으로의 자동 복사를 막습니다. 사용자가 선택해 파일을 가져오는 경우에는 현재 계정에 추가합니다. 로그인하지 않은 이관은 로컬에만 남으며, 서버 왕복 완료를 뜻하지 않습니다.
- 일반 구형 selah.v1 백업, 신형 Selah portable 백업, 3개 언어별 읽기 백업 및 이관 원본 백업을 공통 가져오기 경로에서 처리합니다.
- 다른 origin의 WebView 데이터는 웹페이지가 직접 읽을 수 없습니다. Mac/iOS에서는 기존 앱 데이터 삭제 없이 원본 백업을 내보내고 업데이트 앱에서 같은 계정에 연결하거나 가져와야 합니다. 계정이 합쳐진 인증 오류에는 현재 유효한 계정으로 다시 로그인해야 합니다.
