# Selah feature analytics

The original aggregate endpoint is an anonymous, country-level feature counter. It stores only UTC date, Cloudflare country code, UI locale, feature name, and aggregate count. That endpoint does not store IP addresses, accounts, browser identifiers, Bible passages, or reflection text. `GET /analytics/signup-location` returns only Cloudflare’s country and ISO 3166-2 first-level subdivision code for the current request, with no storage.

The site sends at most one event per feature per browser per UTC day. Counts are approximate browser-days, not people or raw clicks. `/analytics/market` only suggests a UI emphasis after at least 50 aggregate events for a country in the trailing 30 days; otherwise the default UI remains.

Deploy with Wrangler using the configured D1 database. D1 remains on the free plan; do not enable paid features for this project.


The Korea pilot also runs one sticky A/B hero-copy test (`kr-home-copy-v1`). It counts anonymous aggregate exposures, CTA clicks, reading starts, 30-second and 2-minute focus-reading thresholds, new reflection saves, and visits on later days. Experiment rows are grouped by UTC day, Cloudflare country and first-level `regionCode`, interface locale, app/web, coarse device class, and validated UTM source/medium/campaign labels. Only country and `regionCode` are read for geography: city, region name, latitude/longitude, postal code, metro, timezone, and any inferred finer location are ignored. No full user-agent, referrer, raw URL/query, account ID, passage, or note content is stored. Variant assignment and event de-duplication flags remain in browser storage. `GET /analytics/experiment/summary?period=30d` returns recent market rollups and finer rows; `?period=all` returns the retained aggregate history. Daily aggregates remain in D1 for longitudinal research. Treat these as approximate browser counts, never people. Fine splits can be sparse; compare market rollups and do not select a winner below 50 exposures per variant/market or without saved-reading evidence. That threshold is a practical minimum for observation, not statistical or causal proof.

For missing decision-critical data, first name the decision and missing measure. Use an existing official read-only report/API or a small aggregate event only if it answers that question. Never collect finer location, content, raw identifiers, or add paid/complex infrastructure to fill a weak sample; report unavailable data and its limitation instead.

## Optional browser-level usage

Users can explicitly opt in from reader Settings. `/analytics/usage/event` links a random browser UUID to feature use, server receipt time (UTC), country, UI locale, app/web, coarse device type and validated campaign labels. It never receives account identity, passages or note/prayer content. Different browsers/devices remain different IDs: this is not a list of named people or cross-device identities. Events record successful feature handlers; offline events have server receipt time, not the original action time. The original country aggregates continue independently; `bible_downloaded` now matches the client event spelling.

Apply `0004_usage.sql` before deploying this Worker. The browser's queue is capped at 100 events and retries retain the same event UUID to prevent double counting. Each ID has a 500-event UTC-day write cap. Only 30 days are returned and rows older than 30 days are purged on the next usage write or admin read (there is no timed purge job). Withdrawal stops new events, clears pending events and queues server deletion; if offline, the app must next open online to finish deletion.

The existing Developer stats panel contains a Refresh usage button. `/analytics/usage/users` verifies the Bearer session with the fixed BlueCloud developer-proof endpoint on every request; no public endpoint returns browser IDs. No new secret or paid service is required. Authentication failure or unavailability fails closed. The latest 100 browser IDs are listed with per-feature use counts and first/last use; selecting an ID shows up to 200 recent events including campaign/source. Results use `no-store` and the panel clears when hidden. Never paste Bearer tokens into commands, URLs or chat.

Checks: `node scripts/test-usage.mjs`, `node scripts/test-usage-client.cjs`, `node scripts/test-market-experiment-worker.mjs`, `node mobile/scripts/copy-web.mjs --check`. Live collection requires the migration, Worker deployment and web release; native installed versions require a subsequent app build/install.
