# Selah feature analytics

An anonymous, country-level feature counter. It stores only UTC date, Cloudflare country code, UI locale, feature name, and aggregate count. It does not store IP addresses, accounts, browser identifiers, Bible passages, or reflection text. `GET /analytics/signup-location` returns only Cloudflare’s country and ISO 3166-2 first-level subdivision code for the current request, with no storage.

The site sends at most one event per feature per browser per UTC day. Counts are approximate browser-days, not people or raw clicks. `/analytics/market` only suggests a UI emphasis after at least 50 aggregate events for a country in the trailing 30 days; otherwise the default UI remains.

Deploy with Wrangler using the configured D1 database. D1 remains on the free plan; do not enable paid features for this project.


The Korea pilot also runs one sticky A/B hero-copy test (`kr-home-copy-v1`). It counts anonymous aggregate exposures, CTA clicks, reading starts, 30-second and 2-minute focus-reading thresholds, new reflection saves, and visits on later days. Experiment rows are grouped by UTC day, Cloudflare country and first-level `regionCode`, interface locale, app/web, coarse device class, and validated UTM source/medium/campaign labels. Only country and `regionCode` are read for geography: city, region name, latitude/longitude, postal code, metro, timezone, and any inferred finer location are ignored. No full user-agent, referrer, raw URL/query, account ID, passage, or note content is stored. Variant assignment and event de-duplication flags remain in browser storage. `GET /analytics/experiment/summary?period=30d` returns recent market rollups and finer rows; `?period=all` returns the retained aggregate history. Daily aggregates remain in D1 for longitudinal research. Treat these as approximate browser counts, never people. Fine splits can be sparse; compare market rollups and do not select a winner below 50 exposures per variant/market or without saved-reading evidence. That threshold is a practical minimum for observation, not statistical or causal proof.

For missing decision-critical data, first name the decision and missing measure. Use an existing official read-only report/API or a small aggregate event only if it answers that question. Never collect finer location, content, raw identifiers, or add paid/complex infrastructure to fill a weak sample; report unavailable data and its limitation instead.
