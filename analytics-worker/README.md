# Selah feature analytics

An anonymous, country-level feature counter. It stores only UTC date, Cloudflare country code, UI locale, feature name, and aggregate count. It does not store IP addresses, accounts, browser identifiers, Bible passages, or reflection text. `GET /analytics/signup-location` returns only Cloudflare’s country and ISO 3166-2 first-level subdivision code for the current request, with no storage.

The site sends at most one event per feature per browser per UTC day. Counts are approximate browser-days, not people or raw clicks. `/analytics/market` only suggests a UI emphasis after at least 50 aggregate events for a country in the trailing 30 days; otherwise the default UI remains.

Deploy with Wrangler using the configured D1 database. D1 remains on the free plan; do not enable paid features for this project.


The site runs one sticky, locale-specific A/B hero-copy test (`kr-home-copy-v1`, a legacy experiment ID now used across supported country/locale markets). It counts anonymous aggregate exposures, CTA clicks, reading starts, 30-second and 2-minute focus-reading thresholds, new reflection saves, successful username/password signups, and visits on later days. Signup counts are emitted only after the signup endpoint succeeds; they are aggregate conversions, not verified unique people. Google sign-in is not counted because the client cannot safely distinguish a new account from an existing login. Experiment rows are grouped by UTC day, Cloudflare country and first-level `regionCode`, interface locale, app/web, coarse device class, and validated source/medium/campaign labels. Explicit UTM labels are retained in the tab session; absent UTMs, external referrers are reduced to an allowlisted search-engine category or generic referral, with no raw host/query saved. Only country and `regionCode` are read for geography: city, region name, latitude/longitude, postal code, metro, timezone, and any inferred finer location are ignored. No full user-agent, raw referrer, raw URL/query, account ID, passage, or note content is stored. Variant assignment and event de-duplication flags remain in browser storage. `GET /analytics/experiment/summary?period=30d` returns recent market rollups and finer rows; `?period=all` returns the retained aggregate history. Daily aggregates remain in D1 for longitudinal research. Treat these as approximate browser counts, never people. Fine splits can be sparse; compare market rollups and do not change traffic weighting below 50 exposures per variant/market, 3 focused 30-second reads for each variant, and at least one saved reflection across the pair in the last 30 days. After that floor, a variant receives 70% of new anonymous-browser assignments only when its 30-second reading rate is at least 20% higher and its saved-reflection rate is no lower; the other 30% remains a holdout. Region-level weighting is used only when that region meets the same floor; otherwise allocation falls back to country+locale, and stays 50:50 if the evidence is inconclusive. This is a cautious operating heuristic, not statistical significance or causal proof. Assignments stay sticky per browser, country and locale. The ID is retained to avoid a Worker allow-list/deployment dependency; comparisons remain segmented by country, region, locale and landing route, so markets are never pooled to pick a local variant.

The shared static landing-page script also sends `global-funnel-v1` exposure, primary reading CTA, successful reader-open, and first eligible reflection events for its localized entry pages. It uses the same locale/device/source/medium/campaign/landing-route de-duplication key as the web app, so one browser does not count the landing exposure again when it reaches the app with matching context. A short `pending:<timestamp>` reservation prevents both pages from sending the same event during navigation; success marks it complete and failure clears it for retry after the 30-second reservation expires. Small JSON requests use `fetch` with `keepalive` so navigation from a landing page to the reader is less likely to cancel a CTA event. Each event includes only an allow-listed landing-route category (`app`, `localized-landing`, `guide`, `download`, `other`, or `unattributed`) so funnel stages can be compared by entry type. Raw paths and query strings are not added to these experiment rows. Older rows are preserved as `unattributed` by the route migration. Native Capacitor app visits remain excluded from this web acquisition funnel. A missing rollup is still “no recorded event,” not proof of no page visits; compare it with the separate page-view summary and inspect the exact page/locale coverage before diagnosing traffic.

For missing decision-critical data, first name the decision and missing measure. Use an existing official read-only report/API or a small aggregate event only if it answers that question. Never collect finer location, content, raw identifiers, or add paid/complex infrastructure to fill a weak sample; report unavailable data and its limitation instead.


The localized acquisition experiment `localized-arrival-copy-v1` tests one change: the H1 on seven localized landing pages. Variant A keeps the current headline; variant B uses a translated, gentle “start with one chapter and note what stayed with you” invitation. Assignment is sticky in browser storage. Exposure, CTA, reading, reflection and signup events retain the entry variant across the same-tab move into the reader. Country/first-level region and UI locale remain separate dimensions; UI language is not treated as nationality or proof of local demand. Do not call a winner below 50 exposures per variant and market, and require saved-reading evidence before prioritizing a copy. This floor is descriptive, not statistical proof.

Experiment rows now include only one of six allow-listed landing categories. Migration `0005_landing_route.sql` copies historical market aggregates to `unattributed` with counts unchanged. Do not store raw route/query strings, personal identifiers, accounts, or Scripture/reflection content. The A/B change applies only to visible browser landing H1 copy; search metadata and Bible edition promises stay unchanged.
